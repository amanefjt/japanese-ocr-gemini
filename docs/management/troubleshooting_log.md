# トラブルシューティングログ (troubleshooting_log.md)

発生したエラー内容、原因、解決策、再発防止策を記録します。

## [2026-02-12] Git構成の修正
- **事象**: ホームディレクトリがGitルートになっていた。
- **原因**: 以前の作業で不適切に `git init` またはリポジトリが構成されていた可能性がある。
- **対策**: プロジェクトディレクトリを明示的に `git init` し、GitHubリモートを追加。適切な `.gitignore` を設定。

## [2026-03-11] Gitマージコンフリクトの解消
- **事象**: `git push` 時に対向（リモート）との不整合によるコンフリクトが発生。
- **原因**: リモート側で同期版の古いコードがプッシュされていたため。
- **解決策**: コンフリクト箇所を手動で解消し、最新の非同期版コードを整合させた上でマージコミットをプッシュ。

## [2026-03-10] Google GenAI SDK の型エラー
- **事象**: `gemini-2.0-flash` または `gemini-3-flash-preview` 使用時に、`contents` 引数の型エラー（`Input should be an instance of Image` 等）が発生。
- **原因**: SDK のバージョンにより、画像データを辞書形式で渡すとバリデーションエラーになる場合がある。
- **解決策**: `genai.types.Part.from_bytes(data=image_data, mime_type="image/jpeg")` を使用して明示的に Part オブジェクトを生成して渡す。
- **再発防止策**: 型ヒントを活用し、SDK の `types` モジュールを介したオブジェクト生成を標準とする。

## [2026-03-11] Gemini API における長大な待機時間（TTFT悪化）と待機室送り
- **事象**: 特定のページ（Page 06）において、正常なリクエストにもかかわらず、最初の一文字が返るまでの時間（TTFT）が突如として **170秒（約3分）** に跳ね上がる現象が発生。
- **原因の特定**: Google側のAPIサーバーにおいて、リクエストの「計算負荷」が高いと見なされると「低優先度キュー（待合室）」に回され、3〜5分程度のホールドが発生する。
- **トリガー**: 
    - `thinking_level="HIGH"` の使用：活字書籍の単純なOCRに対して推論レベルを上げすぎた。
    - （知見共有より）Structured Output (JSON スキーマ) の使用も同様に優先度を下げる要因となる。
- **解決策**: 
    - `thinking_level="LOW"` を標準採用。Page 06 において **TTFT 170s -> 6.7s** への劇的な改善（約25倍高速化）を確認。
    - 同時に `gemini_ocr.py` に `re` を用いた動的リトライ待機ロジックを実装し、Googleからの `retry in X seconds` 指示に正確に従うようにした。
- **教訓**: Gemini API（特に無料枠）で安定したスループットを得るには、**「モデルへの負荷（推論の深さや制約の複雑さ）を最小化し、サーバー側に『軽いリクエスト』だと思わせること」**が最重要。
