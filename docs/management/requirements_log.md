## [2026-03-11] 最適化と機能統合（低推論レベル・有料版対応・Web刷新）
- **最適化（低推論レベル）**: `thinking_level: LOW` を採用。TTFTを大幅短縮し、API待機時間を極限まで削減。
- **有料版（Paid Tier）最適化**: 有料版ユーザー向けに20並列 / 2000 RPMの「高速モード」をCLI標準搭載。
- **Web UI 刷新**: Web版でも「実行ティア（無料/有料）」の切り替えと、JSによる「レイアウト全自動判定」および並行並べ替えエンジンを搭載。
- **後方互換**: 無料枠ユーザー（15 RPM / 3並列）への配慮として、CLIフラグ（`--free`）およびWeb初期値を設ける。
- **効果**: 平均 TTFT が約 40% 短縮（9秒→5秒）され、特定のページでの異常な遅延（スパイク）が完全に解消。活字書籍の解読には `LOW` が最適であるという知見を確立。

## [2026-03-11] レイアウトの全自動判定アルゴリズムの実順（一段組/二段組の混在対応）
- **アルゴリズム変更**: ユーザーの手動による `--mode` (1/2段組) の指定を廃止し、ページごとに一段組か二段組かを全自動で判定する機能を実装。
- **相対閾値判定 (白黒反転)**: ピクセル値の影響を正確に測るため、画像を白黒反転（文字=白, 背景=黒）し、行のピクセル合計を取得。最も余白が多い行の密度が、ページ全体の平均密度の「20%未満」である場合のみ、明確な段間が存在すると見なして二段組（上下2分割）として処理するロジックを導入。
- **処理順序の確保**: 右ページ・左ページそれぞれに対して判定を行い、一段組なら全体(Full)、二段組なら上下(Top/Bottom)として画像を生成。APIには常に `[右(Top/Bottom/Full) -> 左(Top/Bottom/Full)]` の正しい順序で送信されるようにし、進捗ログにも判定結果を表示するように改善。
