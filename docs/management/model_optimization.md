# Model Optimization Guide: Gemini 3 Flash

Gemini 3 Flash は、最先端の知能を圧倒的なスピードと低コストで提供するモデルです。

> **公式ドキュメント**: https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/gemini/3-flash?hl=ja
https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/gemini/3-1-flash-lite?hl=ja

### 2026-03-11: 推論レベルの最適化（LOWの採用）
- **知見**: 特定の活字ページで `thinking_level: HIGH` を使用すると、AIが「過剰思考（Overthinking）」に陥り、TTFTが170秒を超えるスパイクが発生することが判明。
- **解決策**: `thinking_level: LOW` を採用。これにより、精度を維持したままTTFTが平均約9秒→5秒へと高速化され、スパイクも解消。
- **結論**: 明確な活字書籍のOCRタスクにおいては、`LOW` が最も高いコストパフォーマンスと安定性を発揮するため、これをプロジェクトの標準設定とする。

## ターゲット・モデル
- **MODEL_ID**: `gemini-3.1-flash-lite-preview`
- **THINKING_LEVEL**: `LOW` (標準)

## 1. 推奨モデル構成

| 推奨モデル | 理由 | 備考 |
| :--- | :--- | :--- |
| `gemini-3.1-flash-lite-preview` | **500 RPD** (Free tier) / **高速** (~30%減) | **現在のプロジェクト標準構成** |
| `gemini-3-flash-preview` | 応答が極めて安定。1チャンクあたりの推論が重厚。 | **20 RPD** 制限に注意 |
| `gemini-1.5-flash` | **【廃止済み / 役割終了】** | 知能レベル・コスト面でもはや選択肢になりません。 |

## 2. Thinking Level (思考レベル) の活用

Gemini 3.1 シリーズから導入された `thinking_level` パラメータを制御することで、Lite モデルでも高品質な翻訳・解析が可能です。

- **`HIGH` (高)**: 論理的なステップを細かく実行する。学術論文のレジュメ生成や複雑な構造の翻訳に必須。
- **自動設定**: `llm_client.py` では、モデル名に `gemini-3.1-flash` が含まれる場合に自動で `thinking_level: HIGH` をセットするように実装されています。

### SDK 実装上の注意 (Python)
`google-genai` SDK では、以下のように `thinking_config` のネスト内に配置する必要があります。
```python
config = types.GenerateContentConfig(
    thinking_config = types.ThinkingConfig(thinking_level="HIGH")
)
```

| 項目 | 内容 |
| :--- | :--- |

#### 1回あたり（1ユニット）のデータ量（平均）
- **入力**: 1,300 tokens（画像データ＋OCR指示プロンプト）
- **出力**: 320 tokens（書き起こしテキスト）

#### 合計コストの内訳 (Gemini 3.1 Flash-Lite)
- **入力総計**: 24,700 tokens (1,300 × 19) → **$0.00617**
- **出力総計**: 6,080 tokens (320 × 19) → **$0.00912**
- **一回あたりの実行合計**: **$0.01529**
- **日本円換算**: **約 2.3 円** ($1 = 150円換算)

> [!NOTE]
> **「高速かつ格安」の理由**
> このファイルは見開き5枚を細かく（19枚分に）分割して処理していますが、Gemini 3.1 Flash-Lite は入力 1M トークンあたり $0.25 と極めて安価なため、**これだけ細かく分割してリクエストを投げても、わずか2.3円**で収まります。
>
> **文庫本1冊（100見開き / 200ページ）の試算**:
> 自炊スキャンで一般的な「100見開き」のPDFを処理する場合：
> - 自動レイアウト判定により **200ユニット** に分割して処理。
> - 入力: 260k tokens ($0.065) + 出力: 64k tokens ($0.096) = **$0.161**
> - **合計コスト: 約 24 円**
> 文庫本一冊を丸ごと最高精度でデータ化しても、ペットボトル飲料より遥かに安いコストで運用可能です。
