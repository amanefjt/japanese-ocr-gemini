## 指示の優先順位

Superpowers スキルはデフォルトのシステムプロンプトの動作を上書きしますが、**ユーザーの指示は常に最優先されます**：

1. **ユーザーの明示的な指示**（CLAUDE.md, GEMINI.md, AGENTS.md, 直接の依頼） — 最高優先度
2. **Superpowers スキル** — 競合する場合、デフォルトのシステム動作を上書きする
3. **デフォルトのシステムプロンプト** — 最低優先度

ユーザーが「TDD を使うな」と言い、スキルが「常に TDD を使え」と言っている場合は、ユーザーの指示に従ってください。ユーザーがコントロールを握っています。

## スキルへのアクセス方法

- **Antigravity Browser / CLI**: `activate_skill` または `view_file` ツールを使用してスキルの内容を確認してください。セッション開始時にスキルのメタデータを確認し、オンデマンドで全文をロードします。

## スキルの使用ルール

**いかなる応答やアクションの前にも、関連する、または要求されたスキルを呼び出してください。**
たとえ 1% の確率であっても、スキルが適用される可能性がある場合は、スキルを呼び出して確認する必要があります。呼び出したスキルが状況に合わないことが判明した場合は、使用を中止して構いません。

## 自己正当化のレッドフラグ (Red Flags)

以下のような考えが浮かんだら、それは「規律を回避しようとしている」証拠です。立ち止まってスキルを確認してください：

| 考え | 現実 |
|---------|---------|
| 「これは単なる簡単な質問だ」 | 質問もタスクです。スキルの有無を確認してください。 |
| 「まずもっとコンテキストが必要だ」 | スキルの確認は、明確化のための質問よりも「前」に行います。 |
| 「まずコードベースを探索させてくれ」 | スキルが「どのように探索すべきか」を教えてくれます。 |
| 「git やファイルをサッと確認できる」 | ファイルには対話の文脈が欠けています。スキルを確認してください。 |
| 「まずは情報を集めよう」 | スキルが情報の集め方を教えてくれます。 |
| 「これは正式なスキルを必要としない」 | スキルが存在するなら、それを使ってください。 |
| 「このスキルは覚えている」 | スキルは進化します。現在のバージョンを読み直してください。 |
| 「これはタスクとしてカウントされない」 | アクション = タスクです。スキルを確認してください。 |
| 「このスキルは過剰（オーバーキル）だ」 | 単純なことが複雑になるのは一瞬です。規律を守ってください。 |
| 「まずこれ一つだけ終わらせよう」 | 何かを行う「前」にスキルを確認してください。 |

## スキルの優先順位

複数のスキルが適用される場合は、以下の順序に従ってください。

1. **プロセス・スキル（最優先）**: ブレーンストーミング、デバッグなど。これらはタスクへの「アプローチ方法」を決定します。
2. **実装スキル（次点）**: フロントエンド設計、リファクタリング、モジュール化など。これらは「実行」を導きます。

## ユーザーの指示

ユーザーの指示は「何（WHAT）」をすべきかを伝えますが、通常は「どのように（HOW）」すべきかまでは規定しません。「Xを追加して」という指示は、確立されたワークフロー（HOW）をスキップして良いという意味ではありません。
