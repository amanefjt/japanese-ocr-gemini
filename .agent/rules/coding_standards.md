# コーディング規約と運用ルール (coding_standards.md)

## 1. 言語原則
- **回答言語**: ユーザーへの回答、コード内のコメント、ドキュメントはすべて **日本語** とする。
- **技術用語**: 無理に日本語化せず、正確性を優先して英語（または一般的なカタカナ表記）を維持する。

## 2. ワークフローと承認
- **一括承認原則**: タスク開始前に「作業計画（Implementation Plan）」を提示し、ユーザーから承認（y）を得た場合、その計画に必要なファイル操作（Read/Write）は個別の確認を省略して連続実行する。
- **読み取りの自動化**: コード分析のためのファイル読み取り（Read）は、事後報告のみで自動実行してよい。

## 3. 品質保証と検証
- **ブラウザ検証の義務化**: UI変更やWeb機能の実装時は、必ず Antigravity Browser Extension で動作確認を行う。
- **エビデンスの提示**: スクリーンショットや操作録画を Artifacts として提示する。
- **ブラウザコンソールのエラー確認**: 自律的にブラウザのコンソールログを確認し、エラーがないことを保証する。

## 4. ドキュメント管理
- **リビングドキュメントの維持**: 以下のドキュメントを `docs/management/` に作成し、会話の節目で追記・更新する。
  - `requirements_log.md`: ユーザー要望の時系列集約。
  - `troubleshooting_log.md`: エラー内容、原因、解決策、再発防止策。
  - `task.md`: 目的、DoD、完了済みチェックリスト。
  - `design.md`: 設計方針と採用の根拠。
